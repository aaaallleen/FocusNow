# Allow Time to Run Over Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Settings switch, "Allow time to run over". With it on, a focus that reaches zero keeps counting up (`+4:12`) until Start break, Skip break, or 10 idle minutes. The whole session counts as one finished focus.

**Architecture:**
- **The engine (FocusNowCore) owns the extra time.** At zero it marks the active focus as running over (`ActiveSession.timeUpAt`) instead of finishing it.
- **The existing actions end it.** `start()` (Start break) and `skipBreak()` (Skip break) end the focus with its full active time; an injected idle reading ends it after 10 minutes without input.
- **The app layer only displays and wires.** It shows `clockLabel`, adds the Settings switch, sets the notification text, reads idle time from CGEventSource, and changes how the zero popover dismisses.

**Tech Stack:** Swift 6, SwiftPM (FocusNowCore library + FocusNow app), SwiftUI + AppKit, Swift Testing, macOS 14+.

**Spec:** `docs/superpowers/specs/2026-11-24-run-over-design.md`

## Global Constraints

- **Off by default.** With the switch off, everything behaves exactly as today.
- **Copy, verbatim:**
  - Switch: `Allow time to run over`.
  - Caption: `When a focus reaches zero, the clock keeps counting up until you start your break. The extra time counts as focus. It stops after 10 minutes without keyboard or mouse use.`
  - Notification at zero while running over: title `Focus time is up`, body `The clock keeps running until you start your break.`
- **Extra time display:** `+` followed by `TimeFormat.clock`, so `+04:12` and `+1:02:03`.
- **Scope:** focus sessions only; breaks never run over.
- **Idle limit:** 600 seconds (`TimerEngine.runOverIdleLimitSeconds`). It's checked only while running over and not paused. The focus ends at `max(timeUpAt, now − idle)`.
- **Turning the switch on or off applies at the next zero.** A session already running over keeps going.
- **Self-check:**
  - Runs only through `scripts/self-check.sh`, which uses scratch data via `FOCUSNOW_DATA_DIR`.
  - Never quits, replaces or launches `/Applications/FocusNow.app`.
  - No permission prompts, no activating other apps, and idle time is always faked there.
- **Git:** commit on `feat/run-over` and don't push. Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Owners' existing saved settings must load intact after the upgrade.** Settings are one JSON blob, and a missing key must not reset them. Tested by Task 1 `settingsSavedBeforeRunOverStillLoad`.
2. **A Mac sleep, or a tick gap over 30 s, during the extra time pauses the session without throwing the extra time away.** Tested by Task 2 `blankGapKeepsTheExtraTime`.
3. **A relaunch while running over logs the focus once, as completed, with its extra time up to the last checkpoint, and no flash.** Old snapshots still decode. Tested by Task 2 `relaunchLogsTheFocusAsCompletedWithItsExtraTime` and `snapshotSavedBeforeRunOverStillDecodes`.
4. **Changing the switch mid-session doesn't end or reset anything.** Switching off while running over keeps counting; switching on mid-focus applies at zero. Tested by Task 2 `switchingOffWhileRunningOverKeepsCounting` and `switchingOnMidFocusAppliesAtZero`.
5. **Escape, or a click elsewhere, on the popover that opened at zero closes it and stops the flash, but not the clock.** Tested by the Task 5 self-check line `runover escape`.

### Task 2: The engine keeps a focus running past zero

**Files:**
- Modify: `Sources/FocusNowCore/Model.swift` (`ActiveSession`)
- Modify: `Sources/FocusNowCore/TimerEngine.swift`
- Modify: `Tests/FocusNowCoreTests/TestSupport.swift` (`Harness`)
- Create: `Tests/FocusNowCoreTests/TimerEngineRunOverTests.swift`

**Interfaces:**
- Consumes: `TimerSettings.allowRunOver` (Task 1).
- Produces:
  - `ActiveSession.timeUpAt: Date?` is when the countdown reached zero with run over allowed, otherwise nil. It must be `Optional` so old snapshots decode.
  - `TimerEngine.init(settings:sessions:snapshots:clock:calendar:idleSeconds:)` takes a new last parameter, `idleSeconds: @escaping () -> TimeInterval = { 0 }`.
  - `public static let runOverIdleLimitSeconds: TimeInterval = 600`.
  - `public var isRunningOver: Bool` is true when the active session has a `timeUpAt`.
  - `public var overtimeSeconds: Int` is whole active seconds past the planned length, rounded down; 0 unless running over.
  - `Harness.idleSeconds: TimeInterval` (default 0) is passed to the engine as `{ [unowned self] in self.idleSeconds }`.

**Behaviour:**

- **`tick()` at zero.** If the session is a focus and `settings().allowRunOver` is on:
  - set `timeUpAt = endsAt`;
  - set `needsAttention = true`;
  - call `onFinish?(.focus)` once;
  - save a snapshot;
  - keep the session running.

  Otherwise, finish as today.
- **`tick()` while running over:**
  - Never re-finish at zero.
  - Save a snapshot every `snapshotIntervalSeconds`.
  - If running (not paused) and `idleSeconds() >= runOverIdleLimitSeconds`: finish as `.completed` at `max(timeUpAt, now − idle)`, set `needsAttention = true`, and don't call `onFinish`.
- **`start()` while running over:** finish the focus as `.completed` at `now`, with its full time and without `onFinish`. Then start the next session, which is the break.
- **`skipBreak()` while running over:** finish the same way, then skip the pending break, as `skipBreak()` does for a pending break today.
- **`finish` and `pause(asOf:)`:** don't clamp active time to `plannedSeconds` when `timeUpAt != nil`.
- **`recover(from:)`:** a snapshot whose session has `timeUpAt` is finished as `.completed` at `snapshot.savedAt`, not at `endsAt`, with `notify: false`.
